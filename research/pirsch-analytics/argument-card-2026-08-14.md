# Pirsch Analytics private argument card

- Buyer: a small site, software company, or agency that wants understandable EU-hosted analytics
- Job: measure traffic sources and conversions without maintaining a complicated dashboard
- Thesis: Pirsch is useful when aggregate traffic, events, and funnels answer the team's real weekly questions; it should not replace the old analytics setup until its counts can be reconciled with orders and campaign records
- Main reason to buy: clean cookie-free analytics with server options, events, funnels, and a low entry price
- Main reason to hesitate: thin customer history, lighter deep analysis and ad attribution, and an open-core message that can be mistaken for a free full self-hosted product
- When it is unnecessary: the current dashboard already answers the team's questions clearly and meets its privacy requirements
- Decision rule: run Pirsch beside the current tool for a full campaign and purchase cycle; test browser and server events, duplicates, bots, consent, campaign tags, funnels, imports, exports, and actual source totals; explain every important difference before switching
- Evidence limit: research-based; no Digital Macaroni tracking or legal test
